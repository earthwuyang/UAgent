## Analysis Summary

The bug is confirmed to be a **Redux/Zustand state mismatch** with the following root causes:

1. **State writes go to Zustand** (`agent-store.ts`): The backend sends `AgentStateChangedObservation` events, which are handled in `observations.ts` line 42, calling `setCurrentAgentState(message.extras.agent_state)` which updates the **Zustand store**.

2. **State reads come from Redux** (`store.ts`): Components like `AgentStatus`, `ChatInterface`, and `InteractiveChatBox` all read from Redux using `useSelector((state: RootState) => state.agent.curAgentState)`.

3. **Redux stub has uppercase initial value**: The Redux `agentSlice` in `store.ts` line 29 has `initialState: { curAgentState: "LOADING" }` (uppercase string), while the `AgentState` enum uses lowercase strings like `"loading"`.

4. **Redux is never updated**: The Redux slice has `reducers: {}`, so the state remains stuck at the uppercase `"LOADING"` value forever.

5. **Result**: All comparisons in `AgentStatus.tsx` (lines 45-62) fail because they're comparing the stale uppercase `"LOADING"` against lowercase enum values, causing all conditions to be false and falling back to the clock icon (line 93).

## Proposed Solution (Option A - Recommended)

**Approach A: Migrate components to read from Zustand** ✅ **RECOMMENDED**

**Pros:**
- Minimal changes (only update imports/reads, no new code)
- Aligns reads with writes (single source of truth)
- Removes dead Redux code path
- Clean architecture - Zustand is already the active store
- No risk of sync bugs between two stores

**Cons:**
- Need to update ~15 component files
- Small breaking change if any external code relies on Redux

**Migration scope:** 15 files that use `useSelector((state: RootState) => state.agent.curAgentState)`
